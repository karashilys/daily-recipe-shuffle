## 1. 概要

Minecraftのゲーム内で朝を迎えるたびに、クラフト系レシピの「完成品」が別のレシピの完成品と入れ替わるPaperプラグイン。

- 材料の形・数量は変わらない。その配置で作れる物だけが変わる。
- 例：鉄の剣の配置（鉄インゴット2＋棒）でダイヤのツルハシができる日がある。
- 入れ替えはゲーム内の日が変わるたびに再計算される。ゲーム内の1日は20分なので、遊び続けるかぎり約20分ごとに配置が変わる。

## 2. 動作環境

| 項目 | 内容 |
|---|---|
| サーバー | Paper（Paper API 26.3系） |
| Java | 25 |
| ビルド | Gradle（Kotlin DSL） |
| 依存宣言 | `compileOnly("io.papermc.paper:paper-api:26.3.build.+")` |
| 設定ファイル | `src/main/resources/plugin.yml` |
| メインクラス | `JavaPlugin`を継承し、`Main`ではなく用途が分かる名前にする |

## 3. 用語

| 用語 | 意味 |
|---|---|
| レシピ | 材料の形・数量と完成品を持つ、バニラの1つのレシピ。`NamespacedKey`で識別する |
| 配置 | レシピの材料側。作業台の並べ方、かまどに入れる素材、鍛冶台・石切台に入れる素材など |
| 完成品セット | 完成品アイテムと個数の組。入れ替えの単位 |
| 残り物 | クラフト後に材料側のアイテムが残す物（例：牛乳バケツ→空バケツ、はちみつ瓶→ガラス瓶） |
| プール | 入れ替え対象のレシピ全体 |
| 固定レシピ | 入れ替えず、バニラのまま動作するレシピ |
| 対応表 | 「レシピ → 今日の完成品セット」の写像 |
| 日数 | 基準ワールドの経過tickを24000で割った整数。シャッフルのシードの一部 |
| 基準ワールド | 日数を取得するワールド。メインのオーバーワールドとする |

## 4. 入れ替え対象

### 4.1 プールに含めるレシピ

- 作業台のレシピ（有形・無形。鍛冶型テンプレートの複製を含む）
- かまど、溶鉱炉、燻製器、焚き火のレシピ
- 石切台のレシピ（1つの素材から出る各バリエーションを、それぞれ別のレシピとして扱う）
- 鍛冶台のネザライト強化のレシピ

全レシピを1つのプールとして扱い、レシピの種別をまたいで入れ替える。

データパックや他プラグインが追加したレシピも、バニラのレシピと同じ規則で分類し、プールに含める。追加コンテンツのレシピも入れ替わるほうが、このプラグインの遊びとして一貫するためである。

### 4.2 固定レシピ

- 作業台のレシピ（板材4個の2×2配置→作業台）。作業台を入手できない状況を避けるため固定する。
- 鍛冶台の装飾（トリム）。完成品が材料の組み合わせで決まる特殊レシピのため、入れ替えず、装飾を施す通常の動作を保つ。
- 完成品が材料で決まる特殊レシピ（染色、花火、旗、本のコピー、地図、シュルカーボックスなど）。

### 4.3 対象外

- 醸造
- 村人との取引

### 4.4 板材と棒

板材と棒のレシピは入れ替え対象である。板材は自然生成の建物などのチェストから、棒は木こりの村人のドロップから入手できるため、板材・棒のレシピが入れ替わった日でも進行不能にはならない。

## 5. 入れ替えの規則

### 5.1 完成品セット

入れ替える単位は、完成品アイテムと個数の組である。

- 板材×4を作るレシピの完成品セットが別のレシピに移ると、移った先のレシピは「板材×4」を完成品とする。
- 残り物は材料の性質であり、配置側に残る。ケーキの配置（牛乳バケツ×3など）にツルハシの完成品セットが移ると、ツルハシと空バケツ×3が得られる。ケーキの完成品セットがツルハシの配置に移ると、ケーキだけが得られる。

### 5.2 調理時間と経験値

かまど系レシピの調理時間と経験値は、元のレシピ（配置）側に残る。完成品セットには含めない。時間と経験値はかまどという設備の性質であり、完成品とは独立しているためである。

### 5.3 並べ替えの性質

対応表は次の性質を満たす。

| 性質 | 内容 |
|---|---|
| 全単射 | すべての完成品セットが、ちょうど1つのレシピに割り当てられる |
| 不動点なし | どのレシピも、元の完成品セットのままにならない |
| 決定的 | 同じワールドシードと同じ日数からは、常に同じ対応表が得られる |
| 順序非依存 | レシピの列挙順に左右されないよう、`NamespacedKey`の文字列順に整列してから並べ替える |

保存は不要である。対応表は、ワールドシードと日数から毎回再計算できる。

対応表はプールの内容にも依存する。データパックやプラグインの追加・削除でプールのレシピが増減すると、同じ日数でも対応表全体が変わる。

### 5.4 日数と切り替え

- 日数は、基準ワールド（メインのオーバーワールド）の経過tickを24000で割って求める。プレイヤーが居るワールドに関係なく、すべてのプレイヤーに同じ対応表が適用される。
- 1秒（20tick）ごとに日数を確認し、直前に適用した日数と異なれば対応表を再計算して適用する。
- `/time add`で時間を進めた場合、進めた先の日数に対応する配置に切り替わる。
- `/time set <数値>`で過去の日数に戻した場合、その日数の配置に戻る。同じ日数は常に同じ配置だからである。`/time set`に時刻マーカー（`day`など）を指定した場合は、次にその時刻が来るまで進むため、進めた先の日数の配置に切り替わる。
- 昼夜サイクルが止まっている間は日数が変わらないため、シャッフルも止まる。
- 就寝による夜明けのスキップ、サーバー再起動の後も、日数から同じ対応表が得られる。
- 作業台に材料を並べたまま日数が変わった場合、材料を置き直すまでは切り替え前の完成品が表示され、そのとおりにクラフトされる。表示と結果は一致するため、この挙動を許容する。

## 6. 適用方式

- 対象レシピを実行時にサーバーから削除し、入れ替えた完成品セットで同じキーのまま再登録する。バニラのレシピブックで検索すると、その日の入れ替え後のレシピが表示される。
- 削除と再登録は一括API（`Bukkit.removeRecipes`、`Bukkit.addRecipes`）で行う。1件ずつのAPIは呼ぶたびにレシピ表の再構築と全プレイヤーへの再送を行い、全件の差し替えに数秒かかるためである。一括APIでは、接続2人で約30msに収まる。
- 残り物はバニラのレシピ機構がそのまま返すため、プラグインでは扱わない。

### 6.1 分類と適用の時機

- 分類と適用は、日数を確認する定期処理（5.4）の中で行う。最初の確認はサーバー起動の完了から1秒後とし、他プラグインが起動時に追加するレシピも分類に含める。
- 日数が変わるたびに、全レシピを分類し直してから対応表を適用する。起動後にデータパックや他プラグインが追加・削除したレシピは、次に日数が変わった時点で反映される。
- `/minecraft:reload`などでデータパックを再読み込みすると、レシピは入れ替え前の状態に戻り、次に日数が変わるまでその状態が続く。

## 7. プレイヤー体験

- 今日の対応表を一覧で見る手段は提供しない。
- プレイヤーは、作業台の完成品スロットの表示やレシピブックの検索で、その配置で何ができるかを知る。
- 進行不能になる日があっても、翌日（ゲーム内）に再シャッフルされるため許容する。

## 8. リリース版の制約

- デバッグ用コマンド、隠しコマンド、権限による特別な動作を含めない。
- 動作確認にはバニラの`/time`を使う。
- 検証用の補助機能が必要な場合は、テスト専用のビルドにのみ含め、リリース用のjarには含めない。

## 9. 構成方針

| 層 | 内容 | Bukkit依存 |
|---|---|---|
| コア | レシピ分類、シャッフル、日数計算 | なし（純Java） |
| アダプタ | レシピの削除・再登録、イベント処理、スケジューラ | あり |

コアをBukkitから切り離すのは、シャッフルの性質（5.3）を単体テストで高速に検証するためである。

## 10. テスト戦略

### 10.1 単体テスト（JUnit、純Java）

- 同じシードと日数で同じ対応表になる
- 全単射である
- 不動点がない
- 作業台のレシピ、装飾、特殊レシピ、醸造、取引がプールに入らない
- 日数の計算（tickから日数への変換）が正しい
- 対応表がレシピの列挙順に依存しない

### 10.2 分類テスト（実サーバー）

- 起動時に全レシピを「プール／固定／対象外」に分類し、未分類が1件でもあれば失敗とする。
- Paperのバージョンを上げた際に、追加されたレシピの取りこぼしを検知する。

### 10.3 結果検証（実サーバー）

- `run-paper`で開発用サーバーを起動し、テスト専用のコードで検証する。
- 全レシピの配置を作業台に並べた状態を再現し、完成品が対応表と一致することを確認する。
- かまど系、石切台、鍛冶台も、自動で検証できる範囲を検証する。

### 10.4 手動チェックリスト

- シフトクリックでの連続クラフト
- 完成品セットが入れ替わった配置で、材料側の残り物（牛乳バケツ→空バケツなど）が返ること
- レシピブックの検索結果
- GUIを開いたまま日数が変わった場合の挙動
- `/time add`と`/time set`による切り替え
- 就寝スキップ、サーバー再起動
- 複数プレイヤーの同時操作
- かまど系の調理時間と経験値

### 10.5 再現性

同じ日数なら同じ配置になるため、テスト時は`/time set`で日数を指定すれば、配置を再現できる。
